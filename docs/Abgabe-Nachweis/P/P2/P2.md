## Wo sieht man das?

| Ort | Wie |
|-----|-----|
| **Terminal** (`docker compose up`) | Bei `TAO_VERBOSE=true` druckt das Backend `[TAO NN] … Thought / Action / Observation` |
| **Logs-UI** | Frontend `pages/logs/` – gespeicherte Agent-Logs / Traces |
| **Trace-Persistenz** | `save_trace_node` speichert den Trace (z. B. Trace-ID im Log) |

Code: `trace_service.add_step()`, Config `TAO_VERBOSE`, Graph-Nodes + Agents.

### Wie die Texte entstehen (Composer vs. ReAct)

- **Trace-TAO (Orchestrierung):** Jeder Graph-/Agent-Schritt liefert nur **Workflow-Fakten** (Intent, Node, Agent, RAG-Treffer, Validation, Retries, Artefakt-Kennzahlen). Daraus baut [`tao_composer.py`](../../../../backend/app/graphs/support/tao_composer.py) kurze deutsche Thought/Action/Observation-Zeilen — ohne fest verdrahtete Vollsätze an den Call-Sites und ohne CoT-Dump.
- **ReAct laut VL:** Der echte Multi-Tool-Loop bleibt in `rag_react_node` (`memory_*`, `web_search`, `get_post_data`, `check_post_data_completeness` per Function Calling); die Observation fließt dort in den LLM-Kontext zurück. Der Composer macht denselben Schritt nur **lesbar** im Trace. Tool-Fehler und Validation-Retries erscheinen als eigene TAO-Schritte (`web_search (Fehler)`, `Validation-Retry …`).

Nach dem Umbau: neue Terminal-Screenshots empfohlen (ältere EN-Logs sind veraltet).
